# AGENTS.md

Wails v2 desktop app (Windows). Go backend in `backend/` + React 19 (JSX, no TypeScript) frontend in `frontend/`. There is NO git repo and no JS test/lint framework.

## Commands (run from the right directory — this trips agents up)

- Go module lives in `backend/`. Root has no `go.mod` and the root `package.json` is `{}` (empty — do not npm there).
  - `go build ./...`, `go test ./...`, `go vet ./...` must run in `backend/`.
  - Frontend npm commands (`npm install`, `npm run build`) must run in `frontend/`.
- Scripts at repo root:
  - `build.bat` = `npm install --prefix frontend` → `npm run icons` → `wails build` (in `backend/`) → `build/bin/loganalysis.exe`. This is the normal release build.
  - `dev.bat` = `wails dev` in `backend/` (hot reload; Vite dev server on `127.0.0.1:5173`).
  - `run.bat` = launch the built exe.
- Verification (no lint/typecheck exists): `go vet ./...` + `go test ./...` (in `backend/`), then `npm run build` (in `frontend/`).

## Build gotchas

- `backend/main.go` embeds `frontend/dist` via `//go:embed all:frontend/dist`. That directory is a **generated artifact** (vite `outDir: ../backend/frontend/dist`) and is gitignored. If it is missing, `go build`/`go test` in `backend/` fail with "file not found" for the hashed assets. Run `npm run build` in `frontend/` first (or `wails build`, which runs it automatically via `wails.json` `frontend:build`).
- `wails.json` lives in `backend/`. It also defines the vite dev server URL `http://127.0.0.1:5173`; the vite config binds IPv4 `127.0.0.1` on purpose (WebView2 cannot reach IPv6 `::1`).
- Frontend↔backend bindings (`frontend/wailsjs/go/main/App.js`, `App.d.ts`, `go/models.ts`) are auto-generated by `wails build`/`wails dev`/`wails generate module`. When you add/rename a bound `App` method or change a Go struct's `json` tags, mirror the change in those three files so the frontend compiles before regeneration.

## Architecture

- Backend is a single Go package `main`. The `App` struct (in `app.go`) methods are the IPC surface the frontend calls via `window.go.main.App.*`: `LoadFiles`, `Filter`, `GetPage`, `GetTimeRange`, `GetDetectedFormats`, etc.
- Log parsing pipeline (`parser.go`): `parseLogFile` → parallel chunk scan → `groupRecords` merges continuation lines into **logical records** (one timestamped header + its stack traces/wrapped lines). So "记录数" counts logical records, not physical lines. `Filter` reports `physicalLines`/`foldedLines` computed from `lineSpans()`.
- Format handling:
  - `pattern.go` compiles logback/log4j layout patterns into RE2 regexes (named capture groups: date/level/thread/logger/msg + class/method/etc).
  - `detect.go`: when the user sets no format, `detectFormats` samples several file windows, scores ~40 common patterns (validating date/level/thread/logger and penalizing msg-swallowing), and may return a second pattern for mixed-format files. Fallback is the heuristic `parseLineBasic`.
- Frontend: React 19, all JSX (no TS). Dark-theme CSS in `src/App.css` (CSS variables). `ResultList.jsx` virtualizes rows (`ROW_H=36`). The compare feature (right-click row → compare queue → fullscreen `CompareView` with queue list on top + side-by-side diff) uses the `diff` npm package for char-level diffing — do NOT use `jsdiff` (a stale, incompatible package).

## Repo specifics

- Files and the bundled sample log are UTF-8 with Chinese text; Windows PowerShell console output may render Chinese as mojibake — don't judge correctness from console echo.
- Backend tests that read the bundled sample reference it as `../xxl.log` (they run from `backend/`). Other tests use `t.TempDir()` — no external services needed.
- `backend/go.mod` has a machine-specific `replace` directive pointing to a local wails checkout (`C:\Users\wang\go\pkg\mod`) — may be invalid on other machines.
